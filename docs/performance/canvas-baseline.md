# Canvas performance baseline

Status: M0, M2, and M5 short/15-minute post-GC baselines pass on the documented M5
development host; lower-spec reference-device approval remains pending.

## Canonical fixture

- deterministic seed: `20260801`;
- 200 mixed source/chat/group nodes;
- 300 directed context edges;
- at least 30 nodes in/near the 1440×900 reference viewport during movement;
- one visible ingestion-progress state;
- one visible streaming-chat state;
- progress and streaming payloads update every 250 ms throughout the measurement;
- React Flow `onlyRenderVisibleElements` enabled;
- project-owned domain graph mapped to library types only inside `@siftloom/ui`.

The fixture is generated by `createCanvasFixture()` in `@siftloom/shared`. Unit tests
freeze the node/edge counts, determinism, active status states, and no-self-edge property.
The browser harness also asserts at least 30 rendered nodes; the accepted soak rendered
63 at its initial reference viewport.

## Measurement method

The prototype route `/prototype/canvas` registers a browser-only benchmark controller.
The Playwright harness builds and starts the production Next.js bundle, sets a 1440×900
viewport, performs a real node drag, runs deterministic sine/cosine viewport movement,
sends pointer moves across the canvas, and records:

- `requestAnimationFrame` interval distribution and p95;
- percentage of sampled intervals at or below 20 ms;
- pointer-event timestamp to next animation-frame callback p95;
- longest observed `longtask` entry where supported;
- Chromium `performance.memory` start/end as diagnostic-only values.

During a 15-minute run, the controller remains active after the nominal duration until
the harness completes the final CDP garbage collection and heap read. The harness asserts
that the workload was still active, then explicitly finalizes it. This prevents canvas
reset/render work from contaminating the minute-15 sample.

Run the short local benchmark with:

```bash
pnpm build
pnpm benchmark:canvas
```

Override the duration for the soak:

```bash
CANVAS_BENCHMARK_MS=900000 pnpm benchmark:canvas
```

The harness writes `docs/performance/latest.local.json`. This raw local result is a
diagnostic artifact and must be interpreted with the recorded hardware/browser. CI runs
functional fixture assertions but does not fail on hardware-sensitive frame thresholds.

## Provisional gates to calibrate

| Metric                           | Product-spec proposal |            Accepted 15-minute run | Decision              |
| -------------------------------- | --------------------: | --------------------------------: | --------------------- |
| p95 frame interval               |               ≤ 20 ms |                           17.5 ms | Pass on recorded host |
| Frames at/below 20 ms            |                 ≥ 95% | 99.99% (53,991 sampled intervals) | Pass on recorded host |
| Pointer-to-next-paint p95        |               < 50 ms |                           15.5 ms | Pass on recorded host |
| Longest main-thread task         |              ≤ 200 ms |                             66 ms | Pass on recorded host |
| Post-GC heap growth, minute 5→15 |                 ≤ 20% |                                6% | Pass on recorded host |

The accepted result is
[`runs/m0-2026-08-01-m4-soak-v2.json`](runs/m0-2026-08-01-m4-soak-v2.json). It proves the
implementation and measurement method on this host, not the lower M1-class/8-GiB
reference profile: this machine is materially faster and has more RAM.

The M2 rerun against the editable adapter and versioned payload model is recorded at
[`runs/m2-2026-08-01-m4-soak.json`](runs/m2-2026-08-01-m4-soak.json). It sampled 53,994
frames over 15 minutes with 17.3 ms p95 frame time, 99.99% at or below 20 ms, 15.3 ms
pointer-to-next-paint p95, a 73 ms longest task, and 5.97% post-GC heap growth from minute
5 to minute 15. All calibrated M2 gates pass on the documented host.

The M5 release-candidate rerun is recorded at
[`runs/m5-2026-08-02-soak.json`](runs/m5-2026-08-02-soak.json). It sampled 53,999
frames over 15 minutes with 17.3 ms p95 frame time, 100% at or below 20 ms, 15.8 ms
pointer-to-next-paint p95, no reported long-task entry, and 6.14% post-GC heap growth
from minute 5 to minute 15. The controller was active during the final sample and all
calibrated gates pass on the documented M5 development host.
`latest.local.json` is ignored, overwriteable diagnostic output; accepted evidence is
copied into `runs/` with its machine and source fingerprint.

An earlier diagnostic run is preserved as
[`runs/m0-2026-08-01-m4-soak.json`](runs/m0-2026-08-01-m4-soak.json). It reported 111.26%
heap growth but allowed the controller teardown and minute-15 sample to race. That result
is explicitly marked `diagnostic_failed` and is not acceptance evidence. After the
harness held the workload active through the final sample, the repeat measured 6%.

## Limitations and follow-up

- A frame interval is a useful responsiveness proxy, not a direct GPU paint timestamp.
- `PerformanceObserver` long-task support and `performance.memory` differ by browser.
- A 15-minute Chromium run automatically asks CDP to collect garbage immediately before
  the minute 5 and minute 15 heap samples and proves the controller remains active
  through the final read; the in-page memory value remains diagnostic.
- Native Safari and Edge smoke remain required even when Playwright WebKit/Chromium pass.
- The M2 editor's autosave/conflict path is covered separately by database and
  three-browser tests; this deterministic soak isolates the shared canvas adapter's
  drag/pan, progress, streaming, frame-time, and retained-heap behavior.
